# 无字幕视频的 AI 精读兜底方案（已确认并实现）

> 目标：平台没有人工/自动字幕时，仍能生成字幕、总结、导图和问答；不改动现有下载主流程。

## 1. 现状复核

当前链路：

```
parse → summarize
  → B 站 player/v2（人工 CC / AI 字幕）
  → yt-dlp subtitles / automatic_captions
  → 无字幕：NoSubtitlesError → 前端提示
  → 有字幕：DeepSeek SSE 总结 / 导图 / 问答
```

已确认：

- **B 站 AI 字幕已经可用**：登录态下多数视频返回 `ai-zh`，当前代码已能把 source 标为“哔哩哔哩 AI 字幕”。抽样 12 个视频，10 个有 `ai-zh`。
- **仍存在真空**：
  - `BV1JdNy63EJL`（9:35，VLOG）：无任何字幕。
  - `BV1BPst66EvM`（47:48，访谈）：无任何字幕。
  - 非 B 站平台也可能没有自动字幕。
- **当前 B 站仅音频下载选项有 bug**：`bili-audio` 不匹配 `OPTION_RE`，实际会回退下载完整视频（实测 `BV1JdNy63EJL` 的“仅音频”产出了 170MB MP4）。做 ASR 必须一并修复。
- **本机环境**：Python 3.12、无 GPU、16 个逻辑核、系统无 ffmpeg（已有 `imageio-ffmpeg`）。
- **模型源**：HuggingFace 不可达；ModelScope 可用。

## 2. ASR 可行性实测（已完成）

| 项目 | 实测 |
|---|---|
| 引擎 | `faster-whisper 1.2.1` + CTranslate2 4.9.0 |
| 模型 | ModelScope `Systran/faster-whisper-small`，486MB |
| 模型下载 | 27.7 秒（ModelScope，约 19MB/s） |
| 测试音频 | `BV1JdNy63EJL` 9:35，16k mono WAV |
| 推理 | 93.3 秒，RTF **0.162**（8 CPU 线程，int8） |
| 输出 | 322 段 / 3046 字，自动识别中文（置信度 0.991） |
| 质量 | 开头/结尾可读，存在少量同音字（如“随即”应为“随机”） |
| 结论 | 10 分钟视频约 1.5 分钟；60 分钟视频约 10 分钟；本地 CPU 可行 |

注意：`av 19.0.2` 与 faster-whisper 的路径解码不兼容（`metadata_errors` 参数报错）。方案中用 ffmpeg 输出 16k PCM 后传 numpy 数组，绕过 PyAV 路径解码。

## 3. 推荐方案：三级字幕兜底

```
1. 平台人工字幕 / CC（现有）
2. 平台 AI 字幕（B 站 ai-zh；现有，补强中文优先）
3. 本地 Whisper 语音转写（新增，手动触发）
```

### 3.1 B 站 AI 字幕优先

- 现阶段 `pick_language` 只按 `zh-*` / `en` 排序，`ai-zh` 可能排在 `ai-en` 后面。
- 新增 B 站专用优先级：
  1. 人工中文：`zh-Hans` / `zh-CN` / `zh`
  2. B 站 AI 中文：`ai-zh` / `ai-zh-Hans`
  3. 人工英文 / 其他人工
  4. 其他 AI
- 有 AI 字幕时直接使用，不触发 ASR。速度仍是 1-2 秒级。

### 3.2 本地 Whisper 转写

新增 `backend/asr.py`：

```
summarize(allow_asr)
  ├─ 平台字幕成功 → 原流程
  └─ 无字幕
       ├─ allow_asr=false → 返回 no_subtitles + asr_available + 预估时间
       └─ allow_asr=true
            ├─ 下载音频（B 站 bili-audio / yt-dlp bestaudio）
            ├─ ffmpeg → 16k mono PCM
            ├─ 加载/下载 faster-whisper 模型
            ├─ 逐段转写，SSE 推送进度
            ├─ 生成 SubtitlePayload（source=本地 Whisper 转写）
            └─ 继续 DeepSeek 总结 / 导图
```

关键设计：

| 项 | 选择 |
|---|---|
| 模型 | `small` 默认；486MB；`compute_type=int8`；`cpu_threads=min(8, cpu_count)` |
| 模型缓存 | `backend/models/faster-whisper-small`，gitignore；首次使用从 ModelScope 下载 |
| 触发 | 默认手动按钮；预留 `ASR_AUTO=false` 配置，可改为自动 |
| 时长上限 | 默认 60 分钟，可配置；超限直接拒绝，避免占用 CPU |
| 并发 | 单模型单实例 + 互斥锁；第二次请求排队 |
| 进度 | SSE `status` 增加 `progress`：下载音频 / 加载模型 / 转写 xx% |
| 缓存 | 转写结果复用现有内存 `subtitle_cache`，1 小时内重试总结不重复转写 |
| 临时文件 | `downloads/asr-*`，任务结束删除；不落库 |
| 错误 | `asr_model_missing` / `asr_download_failed` / `asr_timeout` / `asr_failed`；都可回退到原文提示 |
| 隐私 | 本地转写，音频不上传第三方 |

### 3.3 前端体验

**无字幕状态**（SummaryTab / SubtitleTab）：

```
没有平台字幕
可以让 AI 听一遍

[开始语音转写]  [重新提取平台字幕]
机器听写可能有错字，建议对照原视频
```

**转写中**：

- 进度条 + 当前阶段（下载音频 / 准备模型 / 听写 03:20 / 生成为字幕）
- 可以在 SubtitleTab 看到逐段出现（可选：先把已完成分段流式展示）

**转写后**：

- 字幕来源标记：`本地 Whisper 转写`
- 字幕可正常导出 SRT / VTT / TXT
- 总结、导图、问答沿用现有流程
- 增加一行提示：“机器转写可能有错字，建议对照原视频”

```json

```

```json
{"event":"status","data":{"stage":"asr_download","progress":12,"message":"正在下载音频…"}}
```

```json
  "message":"平台没有可用字幕，可以让本地 Whisper 听一遍。",

  "asr_ready":false,
  "estimated_seconds":120,
  "model_size_mb":486
}}
```

## 6. 风险与边界

- 首次下载 486MB；模型下载失败要有明确提示。
- CPU 转写慢于云端；60 分钟视频约 10 分钟，需手动触发并显示预估。
- Whisper small 有同音字/专有名词错误，必须显式提示，不当作人工字幕。
- B 站 AI 字幕依赖登录 Cookie；过期后回到人工字幕/ASR。
- 云 ASR 方案会涉及上传音频、额外 Key 与费用；本方案默认不做。
- 不包含说话人分离、逐字时间轴、翻译；保持现有段落级时间戳。

- 前端无字幕卡片、语音转写入口、进度条、来源标记与错误提示。
