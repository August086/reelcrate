## 3. 对人工方案的关键修正

### 3.1 B 站需要专用适配层，不能只靠 yt-dlp

**问题**：yt-dlp 的 BiliBili extractor 先抓视频网页，本环境返回 412；即使带首页 Cookie，视频页仍 412。
**方案**：`bilibili.py` 直接走公开 Web API：

1. `x/frontend/finger/spi` 获取 `buvid3/buvid4`，建立会话；可选注入 `BILIBILI_SESSDATA`。
2. `x/web-interface/view` 获取标题、封面、UP 主、时长、分 P、cid。
3. WBI 签名调用 `x/player/wbi/playurl` 获取 DASH 视频/音频流。
4. `x/player/wbi/v2` 获取 CC 字幕列表，再拉取 `subtitle_url` 的 JSON 转分段。
5. 下载时按 `baseUrl + backupUrl` 重试，视频/音频分别落盘，ffmpeg `-c copy` 合并。
6. 其他平台仍走 yt-dlp；B 站适配层只处理 B 站，保持改动面最小。

支持 `BV`、`av`、`b23.tv` 短链、分 P。番剧/课程等需要登录的内容返回明确提示，不伪造成功。

### 3.2 下载接口改为“任务 + 轮询 + 文件流”

原方案 `POST /api/download` 直接返回文件流有三个问题：

- 浏览器 `fetch → blob` 会把整部视频读进内存，大文件容易崩；
- 无法显示真实下载进度；
- B 站需要先下载视频+音频再合并，响应会长时间无反馈。

改为：

```
POST /api/downloads       { url, option_id, mode }
  → 直链可用：{ mode: "direct", direct_url, filename }
  → 需要代理：{ mode: "proxy", job_id }
GET  /api/downloads/{id}  → { status, progress, stage, filename, error }
GET  /api/downloads/{id}/file → FileResponse（Content-Length + 中文文件名）
```

任务在临时目录生成文件，完成后 30 分钟自动清理；并发限制 2 个，避免打满服务器。

### 3.3 下载策略：代理优先，直链作为增强能力

原方案“直链优先、失败回退”在真实平台经常失败：直链带时效、Referer/Cookie 防盗链、跨域、B 站 DASH 需要音视频合并。

建议：

- **默认代理**：稳定、可合并、可显示进度、文件名可控。
- **直链**：仅当格式是单文件、服务端 HEAD/Range 校验通过、且平台不需要特殊请求头时返回；B 站/YouTube 等强制代理。
- UI 主按钮只做“下载”，另提供“复制直链”次级操作；直链不可用时禁用并解释原因。
- 自动模式由服务端判断并返回 `direct` 或 `proxy`，前端无需猜。

### 3.4 AI 无 Key 时不伪造结果

- `/api/config` 返回 `ai_enabled`、`ai_model`。
- 无 Key：仍自动提取字幕，字幕 Tab 可用；总结/导图/问答显示“未配置 DEEPSEEK_API_KEY”的设置指引，不生成假摘要。
- 有 Key：解析成功自动触发总结；总结、导图、问答全部 SSE 流式。
- 字幕优先级：`zh-Hans/zh-CN/zh-TW/zh` → `en` → 平台默认；B 站可配置 `SESSDATA` 获取 CC。
- 字幕超长按 40000 字符截断，并在 UI 标注“已截取前 4 万字”。

### 3.5 安全与资源边界

- 仅允许 `http/https`；解析域名并拒绝 localhost、内网、链路本地、云元数据地址（基础 SSRF 防护）。
- URL 长度 ≤ 2048；单任务文件大小上限 2GB；并发 2；临时文件定期清理。
- Markdown 一律经 DOMPurify 清洗后再渲染，防止模型输出 XSS。
- 不在服务端保存用户历史；`.env` 和 `downloads/` 不提交。

## 4. 技术方案

### 4.1 架构

```
浏览器 (Vue3 + Vite + Tailwind)
   │  /api/*
FastAPI
   ├─ url_guard.py         URL 校验 / SSRF 防护
   ├─ downloader.py        yt-dlp 解析、格式归一化、直链探测、代理下载
   ├─ bilibili.py          B 站 API 适配（解析 / 下载 / 字幕）
   ├─ jobs.py              内存下载任务 + 进度 + 清理
   ├─ subtitles.py         VTT/SRT/B 站 JSON 解析
   ├─ summarizer.py        DeepSeek 流式总结 / 导图 / 问答
   └─ main.py              路由、SSE、静态前端
```

不引入数据库、不引入任务队列；单进程内存任务表足够本阶段使用。

### 4.2 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/config` | 平台能力、AI 是否可用、版本 |
| POST | `/api/parse` | URL → 归一化视频信息 + 格式选项 + 字幕语言 |
| POST | `/api/direct-url` | 单文件直链探测（不可用返回 409 + 原因） |
| POST | `/api/downloads` | 创建下载任务，或直接返回直链 |
| GET | `/api/downloads/{id}` | 任务状态 / 进度 / 阶段 |
| GET | `/api/downloads/{id}/file` | 下载文件，支持 Range |
| POST | `/api/summarize` | SSE：subtitle → summary → mindmap → done |
| POST | `/api/chat` | SSE：answer → done |
| GET | `/api/health` | 健康检查 |

格式不做“原始 format_id 列表”直出，而归一化为用户能理解的分级：

```
{ id, label: "1080P 高清", height, ext, filesize, kind: "video"|"audio",
  needs_merge, recommended }
```

B 站格式 ID 使用 `bili-{qn}-{codec}`；其他平台保存 yt-dlp selector，由服务端执行。

### 4.3 AI 流程

1. `parse` 只解析视频，不阻塞总结。
2. 前端解析成功后调用 `/api/summarize`；后端先发 `subtitle`，再发 `summary` 流，再发 `mindmap`，最后 `done`。
3. 总结 Prompt 固定结构：一句话总结 / 内容速览 / 核心要点（尽量带时间戳）/ 适合谁看 / 金句。
4. 导图 Prompt 输出严格 Markdown 树（`# 根节点` + 3~5 个分支，最多 4 层）。
5. 问答只基于字幕上下文，超出范围要明确说“字幕中未提及”。
6. SSE 的 token 用 JSON 编码，避免换行被协议拆断；前端按空行派发事件。

## 5. UI 方向（建议）

### 品牌

**ReelCrate** —— “Keep the good frames. 把好视频，收进匣子。”
Logo：圆角方形胶片框 + 播放三角；主色钴蓝，Pro 用暖金点缀。

### 风格

参考站的白底、蓝色、胶囊、细描边保留，但做三处差异化：

1. **非对称 Hero**：左侧大标题 + 搜索，右侧悬浮“视频卡 + AI 摘要片段 + 清晰度 chip”的胶片叠层，而不是居中大标题 + 瀑布流。
2. **放映室工作台**：解析结果左栏使用深墨蓝（`#0A1020`）放映卡，白色页面中形成强对比；胶片齿孔、时间码作为细节点缀。
3. **付费感**：Pro 卡片深色 + 暖金描边；免费/Pro 对比清晰；不用假支付，按钮明确“即将开放”。

### 页面

1. Header（64px，滚动后毛玻璃）：Logo / 功能 / AI 精读 / 定价 / GitHub / “免费解析”蓝色胶囊。
2. Hero：eyebrow 状态胶囊、主标题、副标题、大搜索框、能力标签、右侧产品预览。
3. 解析结果工作台：左侧放映卡（封面、平台、时长、标题、UP 主、格式网格、下载、直链、AI 按钮）；右侧 4 Tab（总结 / 字幕 / 导图 / 问答）。
4. 能力 Bento：1800+ 平台、原画质、AI 精读、字幕导出、隐私、双下载模式。
5. 平台墙：B 站 / YouTube / TED / 抖音 / TikTok / X / Instagram / Vimeo … + “1800+”。
6. 定价：免费 vs ReelCrate Pro（4K、字幕翻译、批量、优先队列；即将开放）。
7. Footer：免责声明、GitHub、备案占位。

移动端：Hero 单列；结果变上下堆叠；格式横向滚动；下载按钮 sticky 底部；Tab 横向滚动。
